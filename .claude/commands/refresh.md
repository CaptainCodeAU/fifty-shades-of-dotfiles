# /refresh - currency + consistency + gap sweep for fifty-shades-of-dotfiles

You are running the **refresh sweep** for this dotfiles repo: reconcile its docs, per-project memory, and LIVE security/currency posture to ground truth, so the next session opens on facts, not a stale snapshot. This is NOT a docs repo - it is a live config system, so "ground truth" is the installed tool versions, the CVE floors, upstream releases (Zed / pnpm / nvm / Claude Code), stow symlink health, and the version-stamped tracking docs.

**GOLDEN RULE - compute, don't trust.** Never trust a written number/version/status. Derive it live (the Live-signals probes below + the lane commands), then find the docs/memory that disagree. This command hardcodes only stable STRUCTURE (the file map + the deviation guard); every moving value is computed at run time, so the command itself never goes stale.

**REUSE, don't reimplement.** The hard logic already lives in our own scripts - orchestrate them: `toolchain-cve-check`, `pnpm-audit-tree`, `nvm-verify-node`, `git-trailer-audit`, `p10k-contrast-check`, `deploy-parity-check`, `ci-watch` (in `~/.local/bin/`, repo source under `home/.local/bin/`), and the hooks `.claude/hooks/zed-version-check.sh` + `.claude/hooks/session-checks.sh`.

**Mode = `$ARGUMENTS`** (default `all`). Flags compose with any mode.

- **`all`** (blank) - every lane, AUDIT (report + propose, edit nothing).
- **`security`** | **`docs`** | **`memory`** | **`plans`** | **`drift`** | **`telemetry`** - narrow to that one lane.
- **`fix "<term>"`** - targeted: harvest one OLD->NEW pair and audit+apply just that superseded term.
- **`audit`** / **`dry-run`** - hard read-only: make no edits even if `--apply` is also passed.
- **`--apply`** (flag) - after verifying a finding, apply the MECHANICAL, single-correct-answer fix to the WORKING TREE only (sync a drifted floor; bump a CONFIRMED-stale "as of vX" scope stamp + `LAST_UPDATED`; add a memory orphan to the index; repair a dead index link). NEVER stage, commit, or push - the owner reviews `git diff` and commits.
- **`--deep`** (flag) - the security lane also runs the slow `pnpm-audit-tree` recursive audit + `nvm-verify-node` signature re-verify (default security is the fast, cached checks only).
- **`--since <window>`** (flag) - the Phase-1 harvest window, as a `git log --since` string (`'3 weeks ago'`, `2026-07-01`). Default: the LAST RUN date from the stamp below, else `60 days ago` on a first run. Re-harvesting two months of vocabulary on every sweep is wasted work when the last one was yesterday.

Treat everything READ-ONLY unless `--apply` is set (and never in `audit`/`dry-run`).

## Guardrails (non-negotiable)

1. **Read-only until `--apply`.** `audit`/`dry-run` never write. `--apply` edits the WORKING TREE only - **never `git add`, `git commit`, or `git push`.** The owner commits (and gives the push word separately). When you remind them: stage by name, split by concern, never `git add -A`.
2. **Verify every finding yourself** before it is eligible to change (Phase 3). Subagents miscount; drop anything a direct re-probe doesn't reproduce.
3. **Classify before touch: CURRENT-GUIDANCE -> fix, DATED-HISTORICAL -> leave.** A rule/status/"as of installed vX" presented as true NOW that is wrong -> fix. A dated changelog line, a captured note, or a feature-introduction stamp like `NEW (v2.1.83+)` -> LEAVE (it records history).
4. **Surgical edits only** - smallest change that makes the fact current; match tab indentation (`awk '/^\t/{n++} END{print n+0}' <file>` first -- NOT `grep -P`, which only works via Claude Code's ugrep shim; see CLAUDE.md); respect the protect-files / pre-commit hooks. A floor bump edits BOTH files. Never gut a section.
5. **Judgment calls -> a decision-brief** (small table + a recommendation) ending in "Your call:". Do NOT auto-open the AskUserQuestion pop-up. Give a plain-English companion after any dense block.
6. **Compute, don't trust; degrade cleanly.** If a probe/tool can't run (offline, no `$GH_TOKEN`, no `uv`), report SKIPPED - never a false positive. **And a SKIPPED is a finding-CANDIDATE, not a pass.** At report time it is indistinguishable from a miss, so re-probe every SKIP FIRST - bypassing whatever blocked it (sandbox, cache dir, token) - and only then call the lane clean. A lane may not print its clean line while a SKIP in it is unresolved; say what was skipped and why instead. Learned 2026-08-01: a sandbox-blocked docker read was carried as SKIPPED most of a run before anyone re-checked it, and the previous run had reported the same unreadable file as a confirmed defect.
7. **Project boundary + right memory store.** Only this repo and its PER-PROJECT memory store under `~/.claude/projects/<encoded-repo-path>/memory/` (the probes compute the exact path from `$R`; the encoding replaces each `/` in the repo path with `-`). NEVER the repo-root `MEMORY/WORK/` (that is PAI work-tracking, a different store).
8. **Snapshot the memory store before writing to it.** Everything `--apply` touches inside the repo is recoverable with `git checkout`. The memory store is **not a git repository** and has no backup, so an edit there is unrecoverable. Before the FIRST memory-lane write of a run: `cp -R "$M" "${TMPDIR:-/tmp}/memory-backup-$(date +%Y%m%d-%H%M%S)"`, and name the snapshot path in the report. Repo edits need no such ceremony - `git diff` is the undo.

## Phases

Run only the lanes the selected mode needs. Weight the SECURITY lane first.

**Phase 0 - Ground truth.** Read the Live-signals block above; hold it as the truth everything reconciles to. Nothing downstream is hardcoded.

**Phase 1 - Harvest OLD->NEW (self-updating; no baked pairs).** In `fix "<term>"` mode, SKIP the derivation entirely: the term IS the harvest. Resolve its current replacement live (the floor, the version, the renamed path), confirm the OLD form still appears somewhere, then run ONLY the lanes that can contain it - Phases 3-6 unchanged, every other lane skipped and reported as such. A narrowed run must never print the clean one-liner for lanes it did not execute. Derive the superseded vocabulary this run: `git -C "$R" log --since='60 days ago' --pretty=%s | grep -iE 'bump|rename|migrat|supersed|replac|floor|deprecat|->'`; the newest memory supersession markers; and the live-vs-doc deltas from Phase 0 (e.g. doc `v2.1.191` -> live `2.1.201`; Zed doc version -> installed). Hand this list to the audit lanes as the grep terms to hunt.

**Phase 2 - Lanes** (read-only; use parallel `Task` subagents for the big lanes, inline probes for the deterministic ones. **Subagents DISCOVER, they never adjudicate** - they widen the grep, list candidates and cite file:line; the CURRENT-vs-HISTORICAL call and the verdict are yours in Phase 3. That is why guardrail 2 says to drop anything a direct re-probe does not reproduce: the breadth is the value, the judgement is not delegable; feed each the Phase-1 terms; each classifies every hit CURRENT vs HISTORICAL and proposes a surgical fix but applies nothing):

- **SECURITY (first):** the floor-parity + cooldown-parity + ci-watch signals above; then `NO_COLOR=1 toolchain-cve-check` (all three floors + installed pnpm/nvm/bun + the installed **Claude Code** version vs OSV/GitHub advisories; cached). Claude Code has no floor to bump, so an exposure there means `claude update`, not a floor edit - the tool prints the right one. **Only with `--deep`:** `pnpm-audit-tree --fail-on high` over any JS project trees (skip with a one-line note if none), and `nvm-verify-node`. Surface `ci-watch` dormancy as a backlog item; do NOT auto-wire it (a `settings.json` change is a judgment call). Then read the attribution-coverage signal: a **PARTIAL** stamp (exit 1) is a REAL defect - a `commit-msg` hook that started and did not finish - report it; **UNSTAMPED** commits (exit 2) are AMBIGUOUS BY DESIGN - list them and ask, never assert a verdict (deviation guard #13).
- **DOCS currency:** live `claude --version` vs the "as of vX" scope-stamp in the 4 stamped docs (a scope stamp -> bump; a feature-introduction stamp -> leave). - **MEMORY hygiene:** the index-parity signal; then orphans (file not in `MEMORY.md`), dead links (index -> missing file), and dangling `[[wikilinks]]`. Target the per-project store only. **Scope boundary - this lane owns FACTS, not structure.** Fix what has a single correct answer: a stale claim, a moved path, a missing pointer, a dead index link. Do NOT split, merge, relocate, restructure, or rewrite hooks here. Contradictions between two memories, superseded wording still sitting live, foreign content, and an index grown too fat all get FLAGGED and handed to the `MemoryCuration` skill, which owns those and confirms each change with the owner. A flag with no named destination is how a contradiction survives both tools behaving correctly.
- **PLANS backlog:** the open/soon signal; also flag any `Plans/20*.md` spec with NO `Status:` line.
- **DRIFT:** the uncommitted + deploy-parity signal (MISSING / SHADOWED / DANGLING, from `deploy-parity-check`); distinguish intentionally-untracked (leave - deviation guard #5) from a real commit-candidate.
- **TELEMETRY:** the telemetry-posture signal. Anything printed with `>>>` is a tool that is reporting, or relying on a knob that does not cover it. Per the standing rule, an install is not finished until its phone-home is closed; treat a `>>>` as a finding, not a note. Two traps this lane exists for: a global env var is NOT coverage (Homebrew ignores `DO_NOT_TRACK` entirely), and `.zshrc` runs for INTERACTIVE shells only, so a config-file setting beats an exported variable. The `claude` binary's cleared `DO_NOT_TRACK` is a DELIBERATE exception - never flag it.

**Phase 3 - Verify each finding yourself.** Re-read the exact file:line / re-run the specific probe; confirm the OLD value is present AND is CURRENT-GUIDANCE (not dated history) before it is eligible. Discard whatever does not reproduce; note any subagent claim you rejected.

**Phase 4 - Apply (ONLY with `--apply`; skip in `audit`/`dry-run`).** Edit only confirmed current-guidance MECHANICAL hits, minimally, in the working tree. A floor bump edits both files. NEVER commit. Anything destructive or judgment-bearing (delete a dangling symlink, wire `ci-watch`, action a Plan, stage an untracked file, bump an ambiguous stamp) is NOT auto-done -> decision brief.

On drift: a ranked table `{stale -> refreshed / proposed}` per lane, most-severe first; each judgment call as a decision-brief ending in "Your call:"; a plain-English companion after dense blocks; and, if `--apply` ran, the reminder that changes sit UNCOMMITTED in the working tree (review `git diff`; stage by name; split by concern; never `git add -A`). **Then write the run stamp** (always, clean or not, audit or apply): `mkdir -p "${XDG_CACHE_HOME:-$HOME/.cache}/dotfiles" && printf '%s\n%s\n' "$(date +%F)" "<clean|N findings>" > "${XDG_CACHE_HOME:-$HOME/.cache}/dotfiles/refresh-last-run"` - it feeds the staleness signal and the default `--since` window.

**Phase 7 - Self-improving deviation guard (both directions).** If a real drift slipped every probe (or a probe false-fired), PROPOSE - as an Edit to THIS file, shown for approval - a new deviation-guard line or a one-line probe fix. Never self-edit silently; never touch `settings.json` or `CLAUDE.md` on your own.

**And the other direction, which matters just as much: RETIRE guards that a probe now catches.** The guard section only ever grew and is already ~32% of this file; a list nobody finishes reading protects nothing. When a probe starts mechanically detecting what a prose guard describes, propose replacing the prose with a one-line pointer at the probe. When a guard's special case has expired (a file un-ignored, a workaround upstream-fixed, a trial concluded), propose deleting it outright. Same rule as adding: proposed as an Edit, shown for approval, never silent. A guard earns its place by covering something no probe can.

## Deviation guard (dotfiles-specific; the drifts a future session most often repeats; grows via Phase 7)

1. **Stow dangling-link hazard** - checking out a branch that lacks a `home/**` file silently breaks live config (a dangling symlink into the repo). Check `git ls-tree <target> home/` before switching; NEVER "fix" a dangling link by writing a real file over it (that pollutes the tree).
2. **Config-through-symlink pollution** - `pnpm config set`, `git config --global`, and similar write THROUGH the stow symlink into tracked source. Never for temp/machine-local settings on the dev Mac; they surface as repo drift. Machine-local git -> `~/.gitconfig.private`; pnpm temp -> avoid.
3. **Floors live in TWO files** - `PNPM_MIN_VERSION` / `NVM_MIN_VERSION` / `NODE_MIN_MAJOR` / `BUN_MIN_VERSION` in `install.sh` (canonical) AND `home/.zsh_onboarding`. Any bump edits both; assert equality after.
4. **Consumer-box fixes go via `install.sh`** - never hand-patch a consumer box (MLBox/WSL); the deploy path is push -> pull -> `install.sh`. A fix that is not in `install.sh` will not propagate.
5. **Intentionally-untracked - LEAVE alone** - `docs/_CODE_FOLDER_STRUCTURE.md` (real usernames, deliberately untracked), and the machine-private files that never enter the repo: `~/.zshrc.private`, `~/.gitconfig.private`, `.claude/settings.local.json`, Zed `settings.json` (skip-worktree). An empty repo grep for these does NOT mean they don't exist. `home/.local/bin/migrate-claude-projects` is GITIGNORED as of 2026-07-30 (owner's call): local-only, never shipped by stow -> do NOT surface it as a commit candidate, and do NOT propose un-ignoring it.
